# 데모 영상 촬영 계획

`데모-시나리오.md` 를 영상으로 옮기는 각본입니다. 목표 길이 **3분**.

---

## 0. 이 제품을 찍을 때의 함정

**핵심 사건이 눈에 안 보입니다.** 요약이 동료 에이전트에 주입되는 순간은 조용히
일어납니다. 그걸 찍으려 하면 안 됩니다 — **그 결과**를 찍어야 합니다.
누군가 "다른 팀원 뭐 하고 있어?" 라고 묻고 에이전트가 답하는 장면이 그것입니다.

**반대로 판정 화면은 이미 연출이 되어 있습니다.** 단계별로 스스로 열립니다:

```
01 유형 판정   0.9초
02 근거 수집   0.55초
03 조건 검사   0.9초 (조건이 한 줄씩 밀려 들어옴)
04 판정        도장이 떨어짐 · DELETE 면 제목에 취소선이 그어짐
```

여기는 **자르지 말고 통으로** 찍습니다. 배속도 걸지 마세요.

---

## 1. 두 단계로 나눠 찍습니다

라이브로 한 번에 가려 하지 마세요. 세션 요약이 안 올라가거나 최신성이 3시간을
넘으면 그 자리에서 멈춥니다.

### 1단계 · 실제로 끝까지 돌린다 (녹화 없이)

`데모-시나리오.md` 대로 0부~2부를 진행합니다. **판정이 나올 때마다 URL 을 적어 두세요.**

```
장면 1  https://teamsync-ruddy.vercel.app/p/hankki/no-meeting/e/ev-xxxxx
장면 2  .../e/ev-yyyyy
...
```

여기서 기대와 다른 결과가 나오면 그때 고칩니다. **영상에는 실제로 나온 결과만 씁니다.**

### 2단계 · 화면만 다시 찍는다

판정 URL 뒤에 **`?fresh=1`** 을 붙이면 단계별 연출이 **처음부터 다시 재생됩니다.**

```
.../e/ev-xxxxx?fresh=1
```

몇 번이든 다시 찍을 수 있습니다. 조명·타이밍·마우스 움직임을 마음껏 다시 잡으세요.

> 지어낸 화면이 아닙니다. 실제로 나온 판정을 다시 보는 것뿐입니다.

---

## 2. 촬영 원칙 셋

**① 말로 설명하지 말고 화면이 말하게 한다.**
이 제품은 화면에 이유가 다 적혀 있습니다. 나레이션이 그걸 읽으면 지루해집니다.
나레이션은 **"왜 그게 중요한지"** 만 말하고, **무엇이 일어났는지는 화면에 맡깁니다.**

**② 전환은 시간순이 아니라 인과순으로.**
"개발자가 세션을 끝냈다 → (컷) → 디자이너 화면에 그 내용이 있다."
두 컷 사이에 설명을 넣지 마세요. 붙여 놓으면 관객이 스스로 연결합니다.

**③ 결론을 먼저 한 번 보여주고 되감는다.**
첫 10초에 `DELETE` 도장이 찍히는 순간을 넣습니다. 그다음 "어쩌다 여기까지 왔는지"
를 풉니다.

### 1 · 콜드 오픈 (0:00–0:10)

**화면**: 장면 2 판정의 마지막 순간만. `?fresh=1` 로 재생하고 **04 판정** 구간만 씁니다.
`DELETE` 도장이 툭 떨어지고(0.42초), 회의 제목에 취소선이 좌→우로 그어집니다(0.5초).

**촬영**: 도장과 제목이 같이 들어오게 **화면 상단만 크롭**. 전체를 보여주지 마세요 —
아직 아무 맥락이 없어서 글자를 읽으면 산만해집니다.

**자막**: `이 회의는 열리지 않았습니다`

**전환**: 취소선이 끝까지 그어진 프레임에서 **바로 컷.** 여운 주지 마세요.

### 2 · 문제 — 다섯 명이 각자 일한다 (0:10–0:40)

**같은 리듬의 짧은 컷 다섯 개.** 5분할 화면은 쓰지 마세요 — 아무것도 안 읽힙니다.

| 컷 | 화면 | 길이 |
|---|---|---|
| a | 이중희 터미널 — Claude Code 가 `cart/total.ts` 를 고치는 중 | 4초 |
| b | 창현 터미널 — `order/cancel.ts` | 3초 |
| c | 김민성 터미널 — `design/empty-state.md` 문구를 쓰는 중 | 4초 |
| d | 허주영 화면 — Jira 에서 `KAN-4` 를 Highest 로 올림 | 4초 |
| e | 웅이아버지 — 웹 신청서의 빈 제목 칸에 커서가 깜빡임 | 4초 |

**전환**: 전부 하드컷. **같은 길이로 끊어서 리듬을 만듭니다.**

**나레이션**: "다섯 명이 각자 일합니다. 아무도 남이 뭘 하는지 모릅니다."
마지막 컷 e 에서만 한 박자 쉬고 — "그래서 회의를 잡습니다."

> 카메라를 사람 얼굴로 돌리지 마세요. 이 영상에서 얼굴은 정보가 아닙니다.
> 손과 화면만 찍습니다.

### 3 · 장치 — 요약이 흘러간다 (0:40–1:10) ★

**이 영상에서 가장 중요한 30초입니다.**

| 컷 | 화면 | 길이 |
|---|---|---|
| a | 이중희가 세션 종료 (`/exit`), 터미널이 프롬프트로 돌아감 | 3초 |
| b | **(컷)** 김민성 터미널에 `claude` 입력 → 새 세션 시작 | 3초 |

| e | 답변에서 "이중희" "장바구니" 가 나오는 부분 **줌인** | 5초 |

**전환**: a→b 는 하드컷. **사이에 아무것도 넣지 마세요.**

**자막**: 답변이 나오기 시작할 때 화면 아래에
`아무도 보고서를 쓰지 않았습니다`

**나레이션**: 답변이 다 나온 뒤에 한 줄만 — "훅이 세션이 끝날 때마다 요약을

### 4 · 판정 — 신청서를 내면 그 자리에서 (1:10–2:00)

| 컷 | 화면 | 길이 |
|---|---|---|

**전환**: c→d 하드컷. d 안에서는 **절대 컷하지 마세요** — 제품이 스스로 연출합니다.

**자막**:
- e 에서 — `2명이 아직 받지 못했습니다`

### 5 · 증명 — 같은 회의, 참석자만 바꾸면 (2:00–2:35) ★

**좌우 분할. 카메라를 움직이지 마세요.**

```
┌────────────────┬────────────────┐
│  장면 1        │  장면 2        │
│  ASYNC         │  DELETE        │
│  참석 5명      │  참석 3명      │
└────────────────┴────────────────┘
```

**만드는 법**: 두 판정을 각각 `?fresh=1` 로 따로 녹화한 뒤 편집에서 나란히 붙입니다.
**시작 프레임을 맞춰서 동시에 재생되게** 하세요.

| 구간 | 무엇 | 길이 |
|---|---|---|
| a | 두 화면의 **안건 부분**만 하이라이트 — 글자가 똑같음 | 6초 |
| b | 두 화면의 **참석자 부분** 하이라이트 — 여기만 다름 | 6초 |
| c | 두 판정이 동시에 04 단계로 진행 → 도장 두 개가 나란히 찍힘 | 8초 |
| d | 정지. `ASYNC` 와 `DELETE` 를 나란히 보여주며 유지 | 5초 |

**자막**: a 에서 `안건은 한 글자도 바뀌지 않았습니다`
c 직후 `바뀐 것은 거기 앉을 사람뿐입니다`

**나레이션**: d 에서 — "회의가 필요했던 이유가 안건이 아니었다는 뜻입니다."

## 4. 화면 준비

| 항목 | 설정 |
|---|---|
| 해상도 | 1080p 이상 · 60fps (판정 애니메이션이 부드럽게 나옵니다) |
| 터미널 폰트 | **16–18pt 이상.** 평소 크기로 찍으면 아무것도 안 읽힙니다 |
| 터미널 테마 | 어두운 배경 하나로 통일 — 사람마다 다르면 컷이 튑니다 |
| 브라우저 | 전체화면 · 북마크바 숨김 · 확대 110–125% |
| 알림 | **전부 끄기.** 슬랙 배너 하나가 컷을 죽입니다 |
| 마우스 | 커서 강조 도구를 켜세요. 어디를 가리키는지 안 보입니다 |

**배속 규칙**

- 타이핑 · 폼 채우기 → **2–3배속**
- 에이전트 답변 · 판정 화면 → **등속.** 여기가 내용입니다
- 스크롤 → 등속, 천천히

## 5. 위험과 대비

| 위험 | 언제 터지나 | 대비 |
|---|---|---|
| 세션 요약이 안 올라감 | 300자 미만이거나 git 저장소 밖 | 1단계에서 미리 확인. `TEAMSYNC_FORCE=1 claude` |
| `데이터 최신` FAIL | 촬영이 길어져 3시간 초과 | 2부 찍기 직전에 세션 하나 더 |
| 판정이 매번 조금 다름 | 유형 분류가 LLM | **1단계에서 확정하고 URL 을 잡아 두세요.** 2단계는 재생일 뿐 |
| Jira 이슈가 안 읽힘 | 72시간 넘게 갱신 없음 | 촬영일에 이슈 하나 아무거나 수정 |

**리허설을 한 번 하세요.** 0부~2부를 녹화 없이 통으로 돌려서 여덟 장면이 다
문서대로 나오는지 확인한 뒤에 카메라를 켭니다.

## 6. 안 넣는 게 나은 것

- **얼굴 · 회의실 · 사람들이 모여 있는 컷** — 이 제품은 사람을 안 모으는 게 요점입니다
- **아키텍처 다이어그램** — 3분 안에 설명할 수 없고, 화면이 이미 설명합니다
- **판정 화면 배속** — 제품이 만든 리듬을 망칩니다
- **"AI 가 알아서" 같은 문구** — 이 제품은 판단을 사람에게 넘기는 게 특징입니다.
