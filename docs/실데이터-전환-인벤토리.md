# NO MEETING · 실데이터 전환 인벤토리

목데이터가 어디에 남아 있고 무엇으로 바뀌었는지의 기록.
전환할 때마다 이 파일을 갱신한다.

상태 기호 — `완료` / `남음` / `규칙없음`(계산 규칙을 먼저 정해야 함) / `불가`

---

## 0. 이번 라운드에 바뀐 것

**구조 변경 하나가 나머지를 끌고 갔다.** 게이트가 슬라이더 값을 읽던 것을,
근거에 실린 구조화된 값(`Evidence.facts`)에서 계산하도록 바꿨다.
그 결과 M1·M2·M4·M8 이 패치가 아니라 구조적으로 사라졌다.

```
lib/no-meeting/
  types.ts              Evidence.facts · AgendaItem · MeetingRequest · Decider 추가
  settings.ts     신규  조직이 정하는 값 (최신성 기준 · 임계값 · 규칙 버전)
  derive.ts       신규  근거 → 게이트 입력값. 계산 못하면 null(=UNKNOWN)
  engine.ts       개명  (mock-engine.ts) 게이트가 DerivedFacts 만 읽는다
  connectors.ts   분리  커넥터 정의 + `live` 플래그(실물 유무)
  demo.ts         분리  아직 실물 없는 커넥터 몫의 데모 입력만
  evidence-teamsync.ts 신규  context·branches·injections → Evidence
  classify.ts     신규  신청서 자유 텍스트 → 안건·유형 점수·패턴 라벨 (LLM)
  queries.ts      신규  서버 조회 한 벌
  mock-data.ts    삭제
  mock-engine.ts  삭제
  store.tsx       삭제  (sessionStorage → Supabase)
```

## 1. 목데이터 인벤토리

### 1.1 커넥터 — `connectors.ts`

| 항목 | 상태 | 비고 |

| `teamsync` | **완료** | `context`·`branches`·`injections` 실조회. `live: true` |

| 연결 상태 | **완료** | `nm_connections` 테이블 |

### 1.2 큐 한 건 — `MeetingRequest`

| 필드 | 상태 | 출처 |

### 1.3 게이트 입력값 — `derive.ts`

슬라이더가 사라지고 전부 근거에서 계산된다. **계산할 수 없으면 `null` → UNKNOWN → 삭제하지 않는다.**

| 파생값 | 상태 | 근거 |
|---|---|---|
| `lastUpdatedHours` | **완료** | 가장 오래된 근거의 `observedAt` |
| `owner` | **완료** | `context.member` · `branches.reported_by` |
| `undelivered` | **완료 · 신규** | `injections` — 참석 후보 중 아직 주입 못 받은 사람 |
| `agendaCounts` | **완료** | 분류기가 나눈 안건 종류 |
| `ambiguousStatusCount` | **완료** | Task 단위(`taskDone/taskTotal`)로 계산되지 않은 상태 근거의 수 |
| `openValueJudgments` | **완료** | 결정 안건 중 정책으로 답할 수 없는 것 |
| `structuredState` | **완료** | Task 단위 상태 근거의 존재 여부 |
| `checklist` `openP1` | 남음 | 이슈트래커가 붙어야 실데이터 |
| `alertCount` | 남음 | 알림이 붙어야 실데이터 |
| `hypothesisGap` | **불가** | 사람이 정리해 둔 점수만 읽는다. AI 가 매기지 않는다 |
| `freshWithinHours` | **완료** | `settings.ts` 유형별 조직 설정값 |
| `optionCount` | **삭제** | 선택지를 만들기 전에 개수를 검사하는 순환이었다 |
| `sourceOfTruthExists` | **삭제** | 연결 상태로 이미 계산 중이던 중복 |

| 항목 | 상태 | 비고 |

## 2. 구조적 비매칭 — 처리 결과

| | 내용 | 결과 |
|---|---|---|
| **M1** | 근거와 게이트가 연결되어 있지 않다 | **해결** — `derive.ts` 가 유일한 경로 |
| **M2** | 게이트 근거가 `slice()` 로 집힌다 | **해결** — 파생값이 자기 근거를 들고 다닌다 |
| **M3** | 결정 인박스가 두 개다 | **해결** — `decisions` 테이블 한 큐. `/p/[id]/inbox` 신설 |
| **M4** | 재판정 슬라이더 | **삭제** |
| **M5** | 판정을 사람이 눌러서 시작 | **해결** — 신청서를 내면 그 자리에서 판정 |
| **M6** | 커넥터를 연결해도 근거가 늘지 않음 | **해결** — TeamSync 는 실제로 는다. 나머지는 `live:false` 로 명시 |
| **M7** | 결정자 산출 규칙이 없다 | **해결** — `pickDecider()`, 규칙 문장이 `whyYou` 로 표시 |

| **M9** | T3 가 자기 규칙을 위반한다 | **격리** — 사람이 정리한 점수만 읽고, 없으면 UNKNOWN |
| **M10** | 절약 지표가 자기신고값 | **해결** — "열리지 않은 회의 N건" 으로 교체 |

## 3. 알아둘 것 — 새 팀은 T1 이 바로 DELETE 되지 않는다

게이트가 정직해진 대가다. `already_delivered` 는 `injections` 기록이 있어야 검사되고,
기록이 없으면 UNKNOWN 이며, UNKNOWN 이 하나라도 있으면 삭제하지 않는다(ASYNC).

즉 **훅이 실제로 돌아 세션 요약이 오가는 프로젝트에서만 회의가 사라진다.**
이건 버그가 아니라 이 제품의 주장 그대로다 — 요약이 이미 도착했으니 모일 이유가 없다는 것.
다만 데모용 캘린더 요청은 실제 주입 기록이 없으므로 ASYNC 로 끝난다.

## 4. 2차로 끝낸 것

| | 내용 |
|---|---|
| 스키마 적용 | Management API 로 실행 완료. 테이블 5개 + `decisions` 컬럼 4개 |
| **미전달 기록** | `deliveredTo: []`(아무도 못 받음)와 근거 없음(모름)을 구분. 전에는 둘 다 UNKNOWN 이었다 |
| **추천 ③** | `decisions.status='resolved'` → `ANSWER` 근거. 같은 질문을 두 번 묻지 않는다 |
| **추천 ④** | 원장에서 사람별 결정 응답 시간의 **중앙값**을 세서 결정 카드에 표시 |
| **T4 조율** | 게이트 3개. 조율은 데이터로 끝나지 않으므로 DELETE 가 없고 SHRINK 가 기본 |
| **T7 위기** | 판정 대상이 아님을 명시(NOT_APPLICABLE)하고 항상 MEET |
| **자동 재판정** | `/api/ingest` 가 근거를 넣은 뒤 `reevaluateOpen()` 호출. 결론이 그대로면 원장에 남기지 않는다 |
| **신청서 양식화** | 자유 텍스트 한 칸 → 안건(줄 단위) · 산출물 한 줄 · 유형 표식. 분류는 여전히 LLM |
| **회귀 확인** | `npm run check:rules` — DB·LLM 없이 판정 경로 9종을 태운다 |
| **영수증 화면 정리** | `/p/[projectId]` → 회의 판정으로 리다이렉트. "영수증으로 돌아가기" 링크 제거 |

### 신청서 양식 — 넣은 칸과 넣지 않은 칸

| 넣음 | 왜 |
|---|---|
| 안건 · 한 줄에 하나 | 줄만 나누면 분류 정확도가 오른다. 신청자가 쓴 표현을 그대로 쓴다 |
| **이 회의가 끝나면 무엇이 나와야 하나요** | 유형 판정의 가장 강한 신호. 무엇을 만들려는지가 곧 회의 종류다 |
| 유형 표식 (1:1 · 브레인스토밍 · 긴급) | 본문을 읽지 않는 유형. **표식이 있으면 LLM 을 부르지 않는다** — 1:1 내용을 분류기에 보내지 않겠다는 약속이 여기서 지켜진다 |

| 넣지 않음 | 왜 |
|---|---|
| 안건 종류(확인/질의/결정) 선택 | 신청자가 고르면 분류기가 할 일이 없어지고, T8 되묻기도 죽는다 |
| 상태·완료 수치 입력 | 사람이 올리는 건 주장이고, 사실은 커넥터가 준다 |

## 5. 남은 일

1. **커넥터 실물** — 캘린더 · Jira · GitHub · 알림. OAuth 앱 등록이 필요해 코드만으로 끝나지 않는다.
   붙는 순서대로 `demo.ts` 에서 그 몫이 사라진다.
2. **추천 ②의 나머지** — 지금은 근거 소유자만 참석자로 남긴다. `branches` × `context.member` 로
   "이 브랜치에 커밋 N건" 까지 붙이면 처방전의 제외 사유가 더 단단해진다.
3. **고아가 된 파일** — `/p/[projectId]` 가 리다이렉트가 되면서 `components/team-space.tsx`,
   `components/counter-panel.tsx`, `app/preview/page.tsx`, `lib/queries.ts` 의 `getTeamSpace`
   가 아무 데서도 쓰이지 않는다. 카운터 3티어를 되살릴 생각이 없으면 지워도 된다.
