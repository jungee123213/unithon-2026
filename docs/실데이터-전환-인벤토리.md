# NO MEETING · 실데이터 전환 인벤토리

목데이터가 어디에 남아 있고 무엇으로 바뀌었는지의 기록.
전환할 때마다 이 파일을 갱신한다.

상태 기호 — `완료` / `남음` / `규칙없음`(계산 규칙을 먼저 정해야 함) / `불가`

## 0. 이번 라운드에 바뀐 것

**구조 변경 하나가 나머지를 끌고 갔다.** 게이트가 슬라이더 값을 읽던 것을,
근거에 실린 구조화된 값(`Evidence.facts`)에서 계산하도록 바꿨다.
그 결과 M1·M2·M4·M8 이 패치가 아니라 구조적으로 사라졌다.

```
lib/no-meeting/
  types.ts              Evidence.facts · AgendaItem · MeetingRequest · Decider 추가
  settings.ts     신규  조직이 정하는 값 (최신성 기준 · 임계값 · 규칙 버전)
  derive.ts       신규  근거 → 게이트 입력값. 계산 못하면 null(=UNKNOWN)
  engine.ts       개명  (mock-engine.ts) 게이트가 DerivedFacts 만 읽는다
  connectors.ts   분리  커넥터 정의 + `live` 플래그(실물 유무)

  evidence-teamsync.ts 신규  context·branches·injections → Evidence
  classify.ts     신규  신청서 자유 텍스트 → 안건·유형 점수·패턴 라벨 (LLM)
  queries.ts      신규  서버 조회 한 벌
  mock-data.ts    삭제
  mock-engine.ts  삭제
  store.tsx       삭제  (sessionStorage → Supabase)
```

## 3. 알아둘 것 — 새 팀은 T1 이 바로 DELETE 되지 않는다

게이트가 정직해진 대가다. `already_delivered` 는 `injections` 기록이 있어야 검사되고,
기록이 없으면 UNKNOWN 이며, UNKNOWN 이 하나라도 있으면 삭제하지 않는다(ASYNC).

즉 **훅이 실제로 돌아 세션 요약이 오가는 프로젝트에서만 회의가 사라진다.**
이건 버그가 아니라 이 제품의 주장 그대로다 — 요약이 이미 도착했으니 모일 이유가 없다는 것.
다만 데모용 캘린더 요청은 실제 주입 기록이 없으므로 ASYNC 로 끝난다.

### 신청서 양식 — 넣은 칸과 넣지 않은 칸

| 넣음 | 왜 |
|---|---|
| 안건 · 한 줄에 하나 | 줄만 나누면 분류 정확도가 오른다. 신청자가 쓴 표현을 그대로 쓴다 |
| **이 회의가 끝나면 무엇이 나와야 하나요** | 유형 판정의 가장 강한 신호. 무엇을 만들려는지가 곧 회의 종류다 |
| 유형 표식 (1:1 · 브레인스토밍 · 긴급) | 본문을 읽지 않는 유형. **표식이 있으면 LLM 을 부르지 않는다** — 1:1 내용을 분류기에 보내지 않겠다는 약속이 여기서 지켜진다 |

| 넣지 않음 | 왜 |
|---|---|
| 안건 종류(확인/질의/결정) 선택 | 신청자가 고르면 분류기가 할 일이 없어지고, T8 되묻기도 죽는다 |
| 상태·완료 수치 입력 | 사람이 올리는 건 주장이고, 사실은 커넥터가 준다 |

## 5. 남은 일 (2차 시점 기록)

1. **커넥터 실물** — Jira · 알림은 3차에서 끝났다(§6). 캘린더만 남았고, GitHub 은 삭제했다(§7).
2. **추천 ②의 나머지** — 지금은 근거 소유자만 참석자로 남긴다. `branches` × `context.member` 로
   "이 브랜치에 커밋 N건" 까지 붙이면 처방전의 제외 사유가 더 단단해진다.
3. **고아가 된 파일** — `/p/[projectId]` 가 리다이렉트가 되면서 `components/team-space.tsx`,
   `components/counter-panel.tsx`, `app/preview/page.tsx`, `lib/queries.ts` 의 `getTeamSpace`
   가 아무 데서도 쓰이지 않는다. 카운터 3티어를 되살릴 생각이 없으면 지워도 된다.

## 6. 3차로 끝낸 것

### 6.1 바인딩 — 커넥터보다 먼저 막혀 있던 곳

커넥터를 아무리 정확히 붙여도 **근거가 요청에 안 붙으면 UNKNOWN 이고, UNKNOWN 이면
회의를 삭제하지 않는다.** 예전 규칙은 제목·안건과 근거 문장의 단어가 두 개 겹치는지였고,
한국어는 조사가 붙어 `결제를` 과 `결제` 가 다른 토큰이라 실제 신청서에서는 거의 안 붙었다.

`lib/no-meeting/scope.ts` 가 세 축으로 잇는다. **위에서부터, 신청자에게 일을 안 시키는 순서다.**

| 축 | 언제 | 신청자가 할 일 |
|---|---|---|
| `SCOPE` | 제목·본문에 이슈키(`PAY-118`)나 브랜치가 적혀 있을 때 | 없음 (이미 적는 팀은 적고 있다) |
| `PEOPLE` | 부른 사람이 `BIND_WINDOW_HOURS`(72h) 안에 남긴 사실 | **없음 — 기본 경로** |
| `WORDS` | 위 둘이 아무것도 못 잡았을 때만. 조사 보정 포함 | 없음 |

- 어느 축으로 붙었는지를 근거에 남기고(`boundVia`·`boundReason`) 화면에 표시한다.
  `WORDS` 는 대상이 같은지 확인되지 않은 축이라 점선으로 구분해 그린다.
- 신청서의 "관련 이슈·브랜치·서비스" 는 **선택 입력**이다. 범위를 좁히는 용도지 전제가 아니다.
- `meeting_requests.scope_keys` 컬럼 신설.
- **데모가 실경로를 우회하던 것을 없앴다.** 전에는 `demoEvidence[req.id]` 를 통째로 얹어
  줘서 바인딩이 되는지 안 되는지가 데모에서 영영 드러나지 않았다.

### 6.2 커넥터를 실제로 붙이는 흐름

- **저장 전에 실제로 읽히는지 확인한다.** 안 읽히면 연결하지 않는다 — "연결됨" 이라고
  표시해 놓고 근거 없이 UNKNOWN 을 내는 것이 이 제품에서 제일 나쁜 상태다.
- **사람 매핑이 연결 흐름 안에 있다.** 이름이 한 글자만 달라도 `PEOPLE` 축이 0건이 되고,
  화면에는 "확인 불가" 로만 보여 원인을 못 찾는다. 안 맞춘 사람 수를 세어 보여준다.
  글자가 그대로 같을 때만 미리 골라 둔다 — 비슷하다고 짐작해 엉뚱한 사람에게 붙이지 않는다.
- **봇 계정 권고.** 프로젝트당 한 번 붙이면 팀 전체가 그 권한으로 읽으므로,
  연결한 사람이 떠나거나 토큰이 만료되면 팀 전체가 끊긴다.
- 연결 해제하면 자격증명도 지운다. 상태만 바꾸고 토큰을 남기지 않는다.
- 실물이 붙으면 그 커넥터의 목업 근거는 버린다. 아직이면 카드에 "데모 데이터로 동작 중" 이 뜬다.
- `connect/store.ts` 는 `import 'server-only'` 로 시작한다. 토큰이 번들에 섞여 나가는 사고는
  코드 리뷰보다 빌드로 막는 편이 확실하다.

## 7. 커넥터 현황

**남은 커넥터는 셋이고, 전부 판정 조건을 하나 이상 연다.**

| 커넥터 | 여는 조건 |
|---|---|
| `teamsync` | 이미 전달됨 · 담당자 확정 |
| `jira` | Source of Truth · 해석 모호성 · Prerequisite 충족 · 잔존 P1 |
| `alerts` | 증상 재현·계측됨 |

아무것도 열지 않는 커넥터는 두지 않는다. 사람은 연결 화면의 빈 칸을 보고
"저걸 붙이면 판정이 나아지겠구나" 라고 읽기 때문이다.

### 캘린더 — 삭제했다
여는 조건이 0개인 것은 GitHub 과 같았지만, 지운 이유는 더 앞에 있다 —
**판정해도 아무 일이 일어나지 않는 경로였다.**

- 신청서 경로는 닫힌다: 잡으려다 → 판정 받고 → 안 잡는다.
- 캘린더 경로는 안 닫힌다: 이미 잡힌 회의를 읽어 → 판정문이 하나 생기고 → 끝.
  이 제품은 쓰기를 하지 않으므로 일정을 지우지도, 주최자에게 알리지도 못한다.

"판정과 외부 실행은 분리한다" 는 의도된 경계이고 옳다. 다만 캘린더에서는 그 경계 때문에
루프 자체가 닫히지 않았다. 내가 만들지도 않은 남의 회의에 대한 판정문만 쌓인다.

붙이는 비용도 달랐다: `calendar.readonly` 는 Google 민감 범위라 테스트 사용자 밖으로
나가려면 검증이 붙고, 팀 전원이 각자 동의해야 큐가 차며, **캘린더에는 1:1 표식이 없어서**
"1:1 의 제목·본문을 분류기에 보내지 않는다" 는 약속을 지킬 방법이 없었다.

같이 지운 것:
- `lib/no-meeting/demo.ts` — 캘린더 커넥터에 매달려 있던 하드코딩 큐. 시드 스크립트
  (`npm run seed:no-meeting`)가 같은 일을 **DB 에 실제 행으로** 한다. 데모가 실경로를 탄다.
- `RequestSource` 의 `'CALENDAR'` — 이제 출처는 신청서 하나뿐이다.
- `seedConnections` 의 "데모 데이터" 연결. 근거를 지웠는데 연결된 척을 유지하면
  화면은 "연결됨" 인데 판정 근거는 0건이 된다. 이슈트래커·알림은 **끊긴 상태로 시작한다.**

### GitHub — 삭제했다 (여는 조건 0개)
`owner` 와 `merged` 를 둘 다 teamsync 가 이미 공급하고, `owner_identified` 게이트는
값이 있기만 하면 PASS 다. 즉 **붙여도 새로 열리는 조건이 0개**였다.
연결 화면에 서 있기만 하고 아무 조건도 열지 않는 커넥터는, 있는 것보다 없는 편이 정직하다 —
사람은 그 칸을 보고 "저걸 붙이면 판정이 나아지겠구나" 라고 읽기 때문이다.

되살릴 조건: CODEOWNERS 로 관련자를 좁히는 **새 게이트**를 먼저 만들고, 그 게이트가
teamsync 의 `owner` 로는 채워지지 않는다는 것이 확인될 때. 커넥터가 먼저 오지 않는다.
