# 발표 대본 — 6분 · PPT + 캡처

라이브 데모를 하지 않고 **미리 찍은 캡처로 발표**하는 각본입니다.
슬라이드 15장, 정확히 360초. 각 장마다 ① 슬라이드에 넣을 것 ② 어느 캡처를 쓰는지
③ 그대로 읽을 대본 이 있습니다.

- 캡처 원본: https://teamsync-ruddy.vercel.app/p/hankki/no-meeting
- 캡처 목록은 맨 뒤 [찍어야 할 것 16장](#찍어야-할-것-16장) 에 표로 있습니다

> **PPT 로 가는 게 맞는 선택입니다.** 판정은 유형 분류에 LLM 을 쓰므로 낼 때마다
> 결과가 조금씩 다릅니다. 라이브로 가면 그 자리에서 멈출 수 있습니다.
> 캡처는 실제로 나온 판정이고, 발표에서 흔들릴 일이 없습니다.

---

## 이 덱이 지는 짐 두 개

정지 이미지로 옮기면 **두 장면이 죽습니다.** 대책을 먼저 정해 둡니다.

| 죽는 것 | 왜 | 대책 |
|---|---|---|
| 판정 화면이 스스로 열리는 리듬 | 01→04 가 3초에 걸쳐 진행됨 | **조건 6줄을 PPT 애니메이션으로 한 줄씩 등장** (0.3초 간격) |
| 에이전트 답변이 흘러나오는 순간 | 캡처는 이미 다 나와 있음 | 답변 전체 → **한 줄 크롭 확대** 2단 구성 |

나머지는 오히려 캡처가 낫습니다. 특히 `ASYNC` 와 `DELETE` 를 **나란히 놓는 장**은
라이브로는 만들 수 없고 정지 화면에서만 가능합니다. 거기가 이 덱의 정점입니다.

# 슬라이드 2 · 회의의 절반은 확인이다 (30초)

**[슬라이드]** 텍스트만. 캡처 없음.

```
지난주 우리 팀 회의

  결정하려고 모인 자리      ▨▨
  확인하려고 모인 자리      ▨▨▨▨▨▨
```

막대 두 개 또는 숫자 두 개. **문장을 넣지 마세요.**

**[말]**

> 저희 팀은 다섯 명입니다. 개발 둘, 디자인 하나, PM, 마케팅.
>
> 지난주 회의를 세어 봤습니다. 절반은 **누가 뭘 했는지 확인하는 자리**였습니다.
> 결정도 토론도 아니고 확인입니다.
>
> 확인은 원래 회의가 아닙니다. **정보가 도착하지 않아서** 회의가 된 겁니다.

# 슬라이드 3 · 에이전트는 서로를 모른다 (25초)

**[슬라이드]** 다이어그램 한 장. 도형 다섯 개면 충분합니다.

```
   이중희 💻      창현 💻      김민성 💻
      │             │             │
      ✕ ─────────── ✕ ─────────── ✕      ← 서로 모름
      │             │             │
      └──────── 사람이 중계 ────────┘
              git log · PR · "저 이거 했어요"
```

**[말]**

> 그런데 요즘은 다들 AI 에이전트를 씁니다. 각자 자기 터미널에서요.
>
> **에이전트끼리는 서로의 존재를 모릅니다.** 구조적으로 눈이 멀어 있습니다.
> 그래서 사람이 그 눈 역할을 대신합니다. git log 를 훑고, PR 을 확인하고,
> "저 이거 했어요" 를 알립니다.
>
> 그 중계가 쌓이면 회의가 됩니다.

# 슬라이드 4 · 우리가 없앤 것 (25초)

**[슬라이드]** 슬라이드 3과 **같은 자리에 같은 크기**로 그립니다.
✕ 자리에 화살표가 들어가고, "사람이 중계" 줄이 사라지는 그림입니다.

```
   이중희 💻  ──요약──▶  서버  ──주입──▶  창현 💻 · 김민성 💻

   세션 종료 시          팀 관련성 판정         새 세션 시작 시
   자동으로 올라감        민감정보 제외          에이전트에게 들어감
```

> 슬라이드 3 → 4 로 넘길 때 **화면 전환 효과를 쓰지 마세요.** 같은 그림에서
> ✕ 만 화살표로 바뀌는 게 보여야 합니다. (PowerPoint `모핑` 전환이 이 용도입니다)

**[말]**

> 저희가 없앤 게 그 중계기입니다.
>
> 세션이 끝나면 요약이 자동으로 올라가고, 동료가 새 세션을 시작할 때
> 그 요약이 **에이전트에게** 주입됩니다.
>
> 사람은 아무것도 쓰지 않고, 아무것도 읽지 않습니다.

# 슬라이드 8 · 판정 `ASYNC` ★ (45초)

**[슬라이드]** 이 장은 **애니메이션이 필요합니다.** 캡처 **C6** 의 조건 6줄을
잘라서 텍스트로 다시 만들거나, 6줄을 각각 이미지 조각으로 잘라 넣습니다.

```
조건 검사

✓  Source of Truth 존재
✓  데이터 최신
✓  해석 모호성 없음
✕  이미 전달됨              ← 빨강
✓  즉시 토론 불필요
✓  새 결정 없음

                            ASYNC · 비동기 처리
```

**애니메이션 순서**
1. 조건이 위에서부터 **0.3초 간격으로 한 줄씩** 등장 (제품 화면의 리듬 재현)
2. `이미 전달됨` 줄에서 잠깐 멈춤 → 빨간색
3. 클릭 — 캡처 **C7** 확대: *"2명이 아직 받지 못했습니다 — 허주영 · 웅이아버지"*
4. 클릭 — 캡처 **C8**: 후속 조건 문장

**[말]**

> 신청서를 내면 그 자리에서 판정이 돕니다.
>
> (조건이 흐르는 동안 **말하지 않습니다** — 2초)
>
> 조건 여섯 개 중 다섯이 충족되고, 하나가 무너집니다.
>
> (클릭)
>
> **"2명이 아직 받지 못했습니다 — 허주영, 웅이아버지."**
>
> 이 둘은 에이전트를 안 씁니다. PM 은 Jira 를 쓰고, 마케팅은 웹만 씁니다.
> 그러니까 그 내용을 **진짜로 못 받았습니다.** 시스템은 없는 걸 있다고 하지
> 않습니다.
>
> (클릭)
>
> 그리고 이렇게 적습니다 — **"두 사람에게 먼저 흘려보내면 모일 이유가
> 사라집니다."** 회의가 필요한 이유를 **이름으로 특정한** 겁니다.

# 슬라이드 12 · 없애지 않는 것 셋 (35초)

> 신뢰를 만드는 35초입니다. 다 없앤다고 하면 아무도 안 믿습니다.

**[슬라이드]** 3분할. 각 칸에 캡처 크롭 + 한 줄.

| | 캡처 | 화면에 보일 것 |
|---|---|---|
| 왼쪽 | **C12** | 조건이 전부 `해당 없음` |
| 가운데 | **C13** | "AI 는 하나를 고르지 않습니다" |
| 오른쪽 | **C16** | "왜 제가 받았나요" |

**[말]**

> 없애지 않는 것도 정해 뒀습니다.
>
> **1:1 은 조건을 하나도 검사하지 않습니다.** 봐준 게 아니라 애초에 대상이
> 아닙니다. 제목과 본문을 **분류기에도 보내지 않습니다.**
>
> 장애 원인을 찾는 자리는, 배제 못 한 후보가 남아 있으면 모입니다.
> **여기서 AI 는 하나를 고르지 않습니다.** 판단을 사람에게 넘깁니다.
>
> 결정이 필요한 자리는 회의 대신 카드 한 장으로 갑니다. 받는 사람에게
> **"왜 제가 받았나요"** 의 답이 같이 갑니다 — 이 작업의 소유자라서요.

>
> 모르는 걸 "괜찮다" 로 처리하지 않습니다. 없앨 때만 확신이 필요하고,

# 슬라이드 만들 때 지킬 것 다섯

**① 캡처는 크롭해서 크게.** 판정 화면 전체를 한 장에 넣으면 뒷줄에서
아무것도 안 읽힙니다. **필요한 부분만 잘라서 슬라이드를 채우세요.**

**② 빨간 박스는 한 장에 하나.** 두 개 이상이면 시선이 갈라집니다.
슬라이드 11만 예외입니다 (파랑·빨강이 대비를 만드는 게 목적).

**③ 캡처 안의 문장을 슬라이드 제목으로 옮겨 적지 마세요.**
같은 말이 두 번 보이면 관객은 둘 다 안 읽습니다. 제목은 **캡처가 말하지 않는
것**을 말합니다. (예: 캡처에 "2명이 아직 받지 못했습니다" 가 있으면
제목은 `회의의 이유를 이름으로 특정합니다`)

**④ 슬라이드 텍스트는 한 장에 두 줄까지.** 이 대본에 적힌 슬라이드 문구가
전부입니다. 더 넣지 마세요 — 말할 내용을 슬라이드에 적으면 관객이 읽느라
발표를 안 듣습니다.

**⑤ 전환 효과는 슬라이드 3→4 의 모핑 하나만.** 나머지는 전부 없음.

# 예상 질문

**"LLM 이 판정하는 건가요?"**
> 아닙니다. LLM 은 두 군데만 씁니다 — 회의 유형 분류, 세션 요약.
> **조건 검사는 구조화된 숫자로만 합니다.** 완료 3 / 전체 3, 마지막 갱신
> 2시간 전, 주입받은 사람 3명. LLM 이 "이 정도면 80%" 라고 추정한 값은
> 조건 검사에 들어오지 못하게 타입으로 막아 뒀습니다.

**"틀리면요?"**
> 틀리는 방향이 정해져 있습니다. 근거가 없으면 `확인 불가`가 되고,
> 확인 불가가 하나라도 있으면 **회의를 없애지 않습니다.**
> 없앨 때만 확신이 필요하고, 남길 때는 필요 없습니다.

**"내 세션이 다 서버로 올라가나요?"**
> 네 겹으로 거릅니다. ① 프로젝트 폴더에만 설치 ② 브랜치 화이트리스트
> ③ 요약 단계에서 팀 관련성 판정 + 민감정보 제외 ④ 파일 하나 만들면
> 읽기·쓰기가 동시에 멈춥니다. 민감정보는 프롬프트로 한 번, 정규식으로
> 한 번 — 두 번 거릅니다.

**"PM 이 회의에서 빠지는 게 맞나요?"**
> 시스템은 "이 안건의 작업을 실제로 한 사람" 만 근거로 셉니다.
> PM 이 남아야 한다면 그건 사람이 판단할 몫이고, **화면은 그 판단을
> 막지 않습니다.** 판정은 제안이지 실행이 아닙니다 — 일정을 지우지도,
> 이슈 상태를 바꾸지도 않습니다.

**"회의를 다 없애자는 건가요?"**
> 여덟 유형 중 셋은 **아예 판정 대상이 아닙니다.** 브레인스토밍, 1:1,
> 위기 대응. 그리고 조율은 없앨 수 없고 줄이기만 합니다.

**"기존 협업툴과 뭐가 다른가요?"**
> 저 도구들은 **사람이 적어 넣어야** 채워집니다. 이건 아무도 적지 않습니다.
> 에이전트가 이미 만들고 있는 세션 요약을 옮길 뿐입니다.

**"라이브로 보여줄 수 있나요?"**
> 네. (준비돼 있으면 슬라이드 5의 터미널 장면을 실제로 재현)
