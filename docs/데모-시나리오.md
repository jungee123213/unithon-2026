**위에서부터 그대로 따라 하면 됩니다.** 복붙할 프롬프트와 신청서 문안이 다 들어 있습니다.

- 웹: https://teamsync-ruddy.vercel.app
- 화면: https://teamsync-ruddy.vercel.app/p/hankki/no-meeting
- 총 소요: 준비 20분 + 시연 25분

# 0부 · 준비 (한 번만)

## 0-1. 훅 설치 — 세 명 각자

각자 자기 노트북에서, **한끼 배달앱 코드가 있는 폴더**에 설치합니다.

```sh
TEAMSYNC_TOKEN=<웹 프로젝트 화면에서 각자 발급> \
  ./hooks/install.sh <한끼앱_폴더_경로> <본인이름> hankki https://teamsync-ruddy.vercel.app
```

> **이름은 앱에 등록된 표시 이름 그대로** 넣으세요. `이중희` 를 `jungee` 로 넣으면
> 판정이 그 사람을 찾지 못하고, 화면에는 "확인 불가" 로만 나옵니다.

설치 확인:

```sh
cd <한끼앱_폴더> && cat .claude/settings.json | grep TEAMSYNC_MEMBER
```

## 0-2. Jira 이슈 만들기 — 한 사람이

`KAN` 프로젝트에 다섯 개를 만듭니다. **전부 담당자(Assignee)를 지정하세요** —
담당자가 없으면 그 이슈는 어느 회의에도 근거로 붙지 않습니다.

| 키 | 제목 | 서브태스크 | 담당자 | 우선순위 |
|---|---|---|---|---|
| KAN-1 | 장바구니 담기 기능 | 3개 — **전부 Done** | 이중희 | Medium |
| KAN-2 | 주문 취소 플로우 | 3개 — **2개만 Done** | 창현 | Medium |
| KAN-3 | 3.2 릴리즈 QA 체크리스트 | 4개 — **전부 Done** | 김민성 | Medium |
| KAN-4 | 결제 실패 시 이중 청구 | 없음 · **미완** | 창현 | **Highest** |
| KAN-5 | 배달 예상시간 오차 | 없음 · 미완 | 김민성 | Medium |

서브태스크는 이슈를 연 뒤 `Add a child` 로 만듭니다. 이름은 아무거나 (`API` ·
`화면` · `테스트` 정도). **완료 표시는 상태를 `Done` 으로 옮기면 됩니다.**

> 왜 이 모양인가: `KAN-1` 은 "다 끝난 일", `KAN-2` 는 "아직 남은 일",
> `KAN-3` 은 릴리즈 선행 조건, `KAN-4` 는 결정을 만들어 낼 P1 결함입니다.
> 각각이 뒤에서 다른 판정을 만듭니다.

## 0-3. Jira 연결 — 한 사람이

https://teamsync-ruddy.vercel.app/p/hankki/no-meeting/connections
→ **이슈트래커** 카드 → `연결하기`

```
도메인            <사이트>.atlassian.net
이메일            Atlassian 로그인 이메일
API 토큰          id.atlassian.com 에서 발급 (Create API token — with scopes 아님)
```

`확인하고 연결` → 아래 **`2 · 사람`** 에서 Jira 이름을 앱 팀원 이름에 맞춥니다.
→ `사람 매핑 저장`

**여기서 안 맞춘 사람은 그 사람 이슈가 회의에 안 붙습니다.** 화면에는 몇 명이
안 맞춰졌는지 숫자로 나옵니다. 0명이 될 때까지 맞추세요.

# 1부 · 훅을 돌린다 (15분)

회의 판정의 핵심 조건 하나가 **"참석 후보 전원이 이 내용을 이미 주입받았는가"** 입니다.
그걸 만들려면 세 명이 **각자 두 번씩** 세션을 돌려야 합니다.

- 1바퀴: 각자 작업 → 세션이 끝나면 요약이 서버로 올라감
- 2바퀴: 각자 새 세션 시작 → **그때 남들 요약이 내 에이전트에 주입됨**

> 세션 요약이 **300자 미만이면 건너뜁니다.** 아래 프롬프트는 그보다 길게 나오도록
> 만들었지만, 짧게 끝났다면 `TEAMSYNC_FORCE=1 claude` 로 띄우세요.

## 1바퀴 — 세 명이 동시에

각자 자기 폴더에서 `claude` 를 띄우고 아래를 그대로 붙여넣습니다.
**작업이 끝나면 세션을 종료**(`/exit` 또는 Ctrl-D)해야 요약이 올라갑니다.

### 이중희

```
장바구니 담기 기능을 마무리하자. 다음을 순서대로 해줘:

1. 메뉴 상세 화면에서 "담기" 버튼을 누르면 장바구니에 들어가도록 연결
2. 같은 메뉴를 여러 번 담으면 수량이 올라가게 처리
3. 장바구니가 비었을 때 보여줄 빈 화면 문구 추가

각 단계마다 무엇을 왜 그렇게 했는지 설명하면서 진행해줘.
```

### 창현

```
주문 취소 플로우를 이어서 작업하자.

1. 주문 상태가 "조리중" 이후면 취소 버튼을 비활성화
2. 취소 사유를 고르는 화면을 만들고, 고른 값을 서버로 보내는 자리까지 연결
3. 취소가 성공하면 주문 목록으로 돌아가면서 안내 문구 표시

아직 결제 환불 연동은 하지 마. 그건 별도로 정해야 할 게 남아 있어.
```

### 김민성

```
3.2 릴리즈 전에 QA 체크리스트를 코드로 확인하자.

1. 주문 → 결제 → 배달조회로 이어지는 흐름에서 빠진 예외 처리가 있는지 훑어줘
2. 배달 예상시간이 실제와 어긋나는 계산 로직이 있으면 찾아줘
3. 찾은 것들을 우선순위와 함께 정리해줘

고치지는 말고 목록만 만들어줘.
```

**세 명 모두 세션을 종료했는지 확인하고 다음으로 넘어갑니다.**

## 2바퀴 — 주입이 일어나는 순간

각자 `claude` 를 다시 띄웁니다. **띄우자마자** 아래를 붙여넣으세요.

```
지금 이 프로젝트에서 다른 팀원들이 뭘 하고 있는지 네가 알고 있는 대로 말해줘.
```

> **여기가 이 제품의 핵심 장면입니다.** 아무도 보고서를 쓰지 않았는데
> 에이전트가 동료의 작업 내용을 이미 알고 있습니다. 훅이 세션 시작 시점에
> 요약을 주입했기 때문입니다. 이 답변을 캡처해 두세요.

답을 확인했으면 세션을 종료합니다. (이 세션도 요약이 올라갑니다.)

## 장면 1 — 회의가 사라진다 `DELETE`

> 가장 강한 장면입니다. 먼저 하세요.

**신청자: 이중희**

| 칸 | 넣을 것 |
|---|---|
| 제목 | `장바구니 진행 상황 공유` |
| 안건 | 아래 블록 |
| 이 회의가 끝나면 | `각자 어디까지 했는지 공유` |
| 참석 | **이중희 · 창현 · 김민성 전부 체크** |
| 시간 | `30` |

안건 (그대로 붙여넣기):

```
장바구니 담기 기능 어디까지 됐는지
주문 취소 플로우 진행 상황
릴리즈 QA 어디까지 봤는지
```

**나와야 할 결과: `DELETE` — 회의가 열리지 않습니다.**

화면에서 짚을 것:

- **조건 6개가 전부 PASS.** 특히 `이미 전달됨` — *"참석 후보 3명 전원이 이 내용을
  이미 주입받았습니다"*. 1부 2바퀴가 이 줄을 만든 겁니다.
- **`해석 모호성 없음`** — Jira 가 Task 단위로 세어 줬기 때문입니다.
- 근거 목록의 **`부른 사람`** 배지 — 신청자가 이슈 번호를 하나도 안 적었는데
  근거가 붙었습니다. 부른 사람들이 최근에 건드린 것을 찾아온 겁니다.

> 안 되면: `데이터 최신` 이 FAIL 이면 세션이 3시간보다 오래된 것입니다.
> 아무나 짧게 세션 하나 더 돌리고 다시 내세요.

## 장면 2 — 결정 하나만 남는다 `DECIDE`

**신청자: 김민성**

| 칸 | 넣을 것 |
|---|---|
| 제목 | `3.2 릴리즈 Go / No-Go` |
| 이 회의가 끝나면 | `출시 여부 결론` |
| 참석 | 전부 체크 |
| 시간 | `60` |

안건:

```
QA 체크리스트 다 끝났는지 확인
결제 이중 청구 결함(KAN-4)을 안고 출시할 것인가
```

**나와야 할 결과: `DECIDE` — 회의 대신 결정 카드 한 장.**

화면에서 짚을 것:

- **`결정 카드 보기`** 로 들어가면 **"왜 제가 받았나요"** 가 적혀 있습니다.
  수신자는 상수가 아니라 규칙으로 뽑고, 그 규칙 문장을 같이 싣습니다.
- 선택지가 **`그대로 진행` / `보완 후 진행`** 두 갈래인데,
  `cons` 에 **P1 결함 1건** 이 박혀 있습니다 — Jira 의 `KAN-4` 에서 온 숫자입니다.
- 마감이 **회의 예정 시각**입니다. 그 전에 답이 나오면 회의가 필요 없습니다.

**여기서 `보완 후 진행` 을 선택하세요.** 뒤에서 씁니다.

> `Prerequisite 충족` 이 FAIL 이면 `KAN-2` 의 남은 서브태스크가 걸린 겁니다.
> 그게 정상 동작입니다 — 그대로 보여주셔도 좋습니다("아직 남은 게 있으니 NO-GO").
> `DECIDE` 를 보시려면 `KAN-2` 를 전부 Done 으로 옮기고 다시 내세요.

## 장면 7 — 원인을 AI가 고르지 않는다 `SHRINK`

**신청자: 창현**

| 칸 | 넣을 것 |
|---|---|
| 제목 | `결제 이중 청구 원인 조사` |
| 이 회의가 끝나면 | `원인 확정` |
| 참석 | 전부 체크 |

안건:

```
결제가 두 번 청구되는 원인이 무엇인지
```

**"원인을 찾는 자리라면 (선택)"** 칸도 채웁니다:

- 지금 가장 유력하다고 보는 원인: `PG 응답 지연으로 재시도가 두 번 나감`
- 아직 배제하지 못한 다른 가능성:

```
클라이언트 중복 클릭
웹훅 재전송 처리 누락
```
