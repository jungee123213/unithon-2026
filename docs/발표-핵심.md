# 발표 자료용 핵심 정리

발표 자료를 만드는 사람에게 넘기는 문서입니다. **여기 있는 사실은 전부 코드에서
확인한 것**이고, 화면 라벨과 글자가 같습니다. 슬라이드에 옮길 때 이 표기를 그대로
쓰면 화면 캡처와 어긋나지 않습니다.

- 대본: [`발표-대본.md`](발표-대본.md) (슬라이드 15장 · 6분)
- 시연 절차: [`데모-시나리오.md`](데모-시나리오.md)

---

## 한 줄

> **회의가 열리기 전에 판정한다.**

## 세 줄

> AI 에이전트끼리는 서로의 존재를 모릅니다. 그래서 사람이 눈 역할을 대신하고,
> 그 중계가 쌓여 회의가 됩니다.
>
> 세션이 끝나면 요약이 자동으로 동료의 **에이전트**에게 흘러갑니다.
> 아무도 쓰지 않고 아무도 읽지 않습니다.
>
> 그리고 회의를 신청하면, **그 자리에서** 이 회의가 필요한지 근거를 들어 판정합니다.

## 이름

**no meeting** — 회의가 열리기 전에 판정한다

# 제품은 두 부분입니다

발표에서 이 구분이 흐려지면 "그래서 뭐 하는 건데" 가 됩니다.

```
① 세션 요약 훅          ②  회의 판정
   근거를 만든다            그 근거로 판정한다

   Claude Code 훅          회의 신청 → 조건 검사 → 결과
   사람이 안 씀             모든 문장에 근거 링크
```

**①이 없으면 ②가 판정할 게 없습니다.** 다른 도구들이 못 하는 이유가 이것입니다 —
저 도구들은 사람이 적어 넣어야 채워집니다.

---

# ① 세션 요약 훅

## 무엇을 하나

| 시점 | 훅 | 하는 일 |
|---|---|---|
| 답변이 끝날 때 | `Stop` | 마지막 답변을 로컬에 누적 |
| 세션이 끝날 때 | `SessionEnd` | 즉시 백그라운드로 넘김 (세션 종료를 막지 않음) |
| (백그라운드) | — | 범위 판정 → 서버로 전송, 실패하면 큐에 쌓았다가 재전송 |
| 세션을 시작할 때 | `SessionStart` | 동료들의 요약을 받아 **에이전트에게 주입** |

**사람이 하는 일은 0입니다.** 보고서도, 스탠드업도, "저 이거 했어요" 도 없습니다.

## 무엇이 전송되고 무엇이 안 되나 — 네 겹

| 계층 | 규칙 |
|---|---|
| **범위** | 그 프로젝트 폴더에만 설치. 다른 프로젝트 세션은 안 올라감 |
| **브랜치** | 화이트리스트에서만 (기본 `main` · `develop` · `feature/*`) |
| **내용** | 요약 단계에서 팀 관련성 판정 + 민감정보 제외를 **동시에** |
| **예외** | `.teamsync-off` 파일 하나면 **읽기·쓰기가 동시에** 멈춤 |

민감정보는 **프롬프트로 한 번, 정규식으로 한 번 — 두 번** 거릅니다.
300자 미만 세션은 아예 건너뜁니다.

## 한 번에 세 벌을 뽑습니다

한 문장을 두 독자에게 쓸 수 없어서, 요약 한 번에 세 벌이 나옵니다.

| 필드 | 읽는 쪽 | 예 |
|---|---|---|
| `summary` | 동료의 **에이전트** | "injections 테이블에 batch_id·rendered 컬럼을 추가했습니다" |
| `summary_plain` | 이 프로젝트의 **비개발자** | "동료에게 실제로 전달된 문장을 화면에 그대로 보여줄 수 있게 저장 구조를 바꿨습니다" |
| `work_label` | 문서 섹션 제목 | "영수증 화면" |

> **`work_label` 은 사실이 아니라 명명입니다.** 브랜치명이 `fix2` 여도 문서가
> 읽히게 하려고 넣었습니다.

# ② 회의 판정

## 흐름

```
회의 신청서  →  01 유형 판정  →  02 근거 수집  →  03 조건 검사  →  04 판정
                (LLM)          (커넥터 3곳)      (숫자만)        (5종)
```

**신청서에 넣는 것**: 제목 · 안건(줄 단위) · "이 회의가 끝나면 무엇이 나와야 하나" ·
참석 후보 · 예정 시간. 원인 조사면 "유력한 원인" 과 "아직 배제 못 한 가능성" 도.

## 회의 유형 8종

| 코드 | 유형 | 어떻게 다루나 |
|---|---|---|
| T1 | 정보 공유 / Status | 조건 6개 검사 |
| T2 | 의사결정 | 조건 4개 검사 |
| T3 | 문제 해결 | 조건 5개 검사 |
| T4 | 조율 / Planning | 조건 3개 — **없앨 수 없고 줄이기만** |
| T5 | Brainstorming | **분해하지 않습니다.** 항상 엽니다 |
| T6 | Feedback / 1:1 | **제목조차 읽지 않습니다.** 항상 엽니다 |
| T7 | 갈등 / 위기 | **판정으로 늦추지 않습니다.** 즉시 엽니다 |
| T8 | 미분류 | **되묻습니다.** 결론을 내지 않습니다 |

> **여덟 중 넷(T5·T6·T7·T8)은 애초에 판정 대상이 아닙니다.** 봐준 게 아니라
> 대상이 아닙니다. 발표에서 이 말을 꼭 넣으세요 — 신뢰는 여기서 생깁니다.

## 판정 결과 5종

| 결과 | 화면 라벨 | 뜻 | 산출물 |
|---|---|---|---|
| `DELETE` | **회의 없음** | 조건을 전부 충족. 열리지 않아도 됩니다 | 해결 로그 |
| `ASYNC` | **비동기 처리** | 모이지 않고 끝내되, 조건 하나가 남았습니다 | 해결 로그 |
| `DECIDE` | **사람 결정** | 가치판단 한 건만 남았습니다 | **결정 카드** |
| `SHRINK` | **축소 개최** | 더 적은 사람과 더 짧게 엽니다 | 회의 처방전 |
| `MEET` | **회의 유지** | 없앨 수 없습니다 | 회의 처방전 |

## 조건 상태 4종

| 표시 | 뜻 |
|---|---|
| **✓ 충족** | 근거로 확인됐습니다 |
| **✕ 미충족** | 근거로 확인했는데 조건에 못 미칩니다 |
| **? 확인 불가** | 근거가 없어서 못 봤습니다 — **FAIL 이 아닙니다** |
| **— 해당 없음** | 이 유형에는 적용하지 않습니다 |

> **확인 불가가 하나라도 있으면 회의를 없애지 않습니다.**
> 이게 이 제품의 안전 규칙입니다. 성능이 아니라 규칙입니다.

## 조건 목록 (T1 정보 공유 기준 · 데모에서 보이는 것)

| 조건 | 무엇을 보나 |
|---|---|
| Source of Truth 존재 | 안건 상태를 Task 단위로 셀 수 있는가 |
| 데이터 최신 | 최종 갱신이 기준 시간 안인가 |
| 해석 모호성 없음 | 모든 상태 근거가 완료/전체로 계산됐는가 |
| **이미 전달됨** | **참석 후보 전원이 이 내용을 이미 주입받았는가** |
| 즉시 토론 불필요 | 답이 아직 없는 질의형 안건이 0건인가 |
| 새 결정 없음 | 새로 내려야 할 결정이 0건인가 |

> **`이미 전달됨` 이 이 제품만 가진 조건입니다.** 다른 어떤 도구도 이걸 셀 수
> 없습니다 — 요약이 실제로 누구에게 흘러갔는지 기록이 있어야 하기 때문입니다.

# 기능 목록

## 화면 8개

| 화면 | 하는 일 |
|---|---|
| **오늘** | 회의 신청서 · 판정 대기 큐 · 최근 판정 |
| **판정 상세** | 01 유형 → 02 근거 → 03 조건 → 04 판정. `?fresh=1` 로 재생 가능 |
| **결정 카드** | 결정 한 건. **"왜 제가 받았나요"** 가 같이 붙습니다 |
| **회의 처방전** | 없앨 수 없을 때 — 참석자·안건·종료 조건을 줄여서 냅니다 |
| **결정 인박스** | 훅이 뽑은 결정과 판정이 만든 결정이 **한 큐로** |
| **결정 원장** | 판정 · 결정 · 되돌림이 시간순으로. 정책도 여기서 |
| **진행사항** | **비개발자용** 작업 현황 (작업별 / 사람별) |
| **연결** | 커넥터 연결 · 사람 이름 매핑 |

## 기능 12개

**1. 근거 자동 수집**
신청자가 이슈 번호를 하나도 안 적어도 근거가 붙습니다. **부른 사람들이 최근
72시간 안에 건드린 것**을 찾아옵니다.

**2. 조건 검사는 숫자로만**
조건은 구조화된 값만 읽습니다 — 완료 3 / 전체 3, 갱신 2시간 전, 주입받은 사람 3명.
**요약 문장은 읽지 않습니다.** LLM 이 추정한 값이 조건에 들어오지 못하게 타입으로
막았습니다.

**3. 되묻기 (T8)**
유형 1·2위 점수 차가 **0.20 미만**이면 결론을 내지 않고 목적을 한 줄 되묻습니다.
*"여기서 하나를 고르면 그 뒤의 모든 판정이 틀린 전제 위에 서게 됩니다."*

**4. 참석자 추리기**
근거에 실제로 등장하는 사람만 남기고, **각자 왜 남았는지 / 왜 빠졌는지** 이유가
붙습니다. 관련도를 퍼센트로 추정하지 않습니다 — **기록에 있거나 없거나**입니다.

**5. 결정 수신자 자동 지정 + "왜 제가 받았나요"**
받는 사람은 상수가 아니라 규칙으로 뽑고, **규칙 문장을 같이 싣습니다.**
*"결정 안건에 걸린 작업의 소유자입니다."*
→ **PM 이 회의를 신청했는데 결정은 개발자에게 갑니다.**

**6. 선택지를 지어내지 않음**
`그대로 진행` / `보완 후 진행` 두 갈래가 뜨는데, `cons` 의 **"P1 결함 1건"** 은
이슈트래커에서 읽어 온 숫자입니다.

**7. 마감 = 회의 예정 시각**
그 전에 답이 나오면 회의가 필요 없습니다.

**8. 같은 질문을 두 번 묻지 않음**
이미 어딘가에서 답이 나온 안건은 **빼고 셉니다.** 회의가 아니라 링크 하나로 끝납니다.

**9. 자동 재판정**
새 세션 요약이 들어오면(=근거가 바뀌면) 아직 열리지 않은 회의를 **다시 판정합니다.**
결론이 그대로면 아무것도 남기지 않고, **사람이 이미 손댄 건은 건드리지 않습니다.**

**10. 결정 원장**
되돌린 결정은 **지우지 않고 이벤트를 하나 더 붙입니다.** 판정마다 그때의 규칙
버전이 박혀 있어서 "그때 무슨 규칙으로 그렇게 판정했는지" 가 남습니다.

**11. 정책 승격**
같은 판단이 **3번** 반복되면 정책 후보로 올라옵니다. 정책이 생기면 그다음부터는
사람에게 다시 묻지 않습니다. **되돌린 결정은 빼고 셉니다** — 잘못된 판단이 정책으로
굳는 걸 막습니다.

**12. 비개발자용 진행사항 문서**
개발자가 보고서를 쓴 적이 없는데 작업 현황이 문서로 있습니다.
**진행률을 추정하지 않습니다** — 상태는 git 머지 여부에서만 옵니다.

| 상태 | 판정 근거 |
|---|---|
| 기준 브랜치 | `main` · `master` · `develop` |
| 머지됨 | `git branch --merged` 에 있음 |
| 진행중 | 머지 전 + 마지막 기록 24시간 이내 |
| 멈춤 | 머지 전 + 24시간 넘게 기록 없음 |

# 근거는 어디서 오나 — 커넥터 3

**이 제품은 스스로 사실을 만들지 않습니다.** 전부 남의 시스템에서 읽어 옵니다.

| 커넥터 | 무엇을 읽나 | 무슨 조건을 여나 | 쓰기 |
|---|---|---|---|
| **세션 요약** (이 앱의 훅) | 세션 요약 · 브랜치 병합 상태 · 누구에게 흘러갔는지 | 상태 근거 · 최종 갱신 · 작업 소유자 · **이미 전달됨** | 읽기 전용 |
| **이슈트래커** (Jira) | 이슈 상태 · 체크리스트 · 결함 등급 | Task 단위 상태 · Prerequisite · 잔존 P1 | **상태 변경·코멘트 안 함** |
| **장애 알림** (Sentry · Discord) | 5xx · 예외 추이 · 장애 스레드 | 증상 계측됨 | **알림 삭제·글쓰기 안 함** |

> **연결을 끊으면 조건이 미충족이 아니라 `확인 불가` 가 되고, 결과가
> `DELETE` 에서 `ASYNC` 로 바뀝니다.** 근거가 없으면 없앨 수 없습니다.

# 하지 않는 것 (차별점)

발표에서 **가장 잘 먹히는 목록**입니다. 다 없앤다고 하면 아무도 안 믿습니다.

| 안 하는 것 | 이유 |
|---|---|
| 일정을 만들거나 지우지 않음 | 캘린더에 연결하지 않습니다 |
| 이슈 상태 변경 · 코멘트 안 함 | 판정과 외부 실행은 분리돼 있습니다 |
| **진행률 · 확률 · 점수 추정 안 함** | 화면의 모든 숫자는 어딘가에서 읽어 온 값입니다 |
| **관련도를 % 로 추정 안 함** | 기록에 있거나 없거나입니다 |
| **원인을 AI 가 고르지 않음** | 배제 못 한 후보가 남으면 사람에게 넘깁니다 |
| **1:1 본문을 분류기에 안 보냄** | 표식을 사람이 직접 다는 이유가 이것입니다 |
| 기여도 · 업무량 안 셈 | "지금 하는 일" 이 아니라 "가장 최근 기록" 이라고 씁니다 |
| **확인 불가면 안 없앰** | 모르는 것을 "괜찮다" 로 처리하지 않습니다 |

# 그대로 써도 되는 문장

슬라이드 카피로 쓰세요. **전부 실제 화면에 나오는 문장**이거나 그 요약입니다.

**제목용**

- 회의가 열리기 전에 판정한다
- 확인으로 끝나는 일은 회의가 되지 않는다
- 회의를 없애는 게 아니라, 없어도 되는 회의를 찾아냅니다
- 아무도 보고서를 쓰지 않았습니다
- 안건은 한 글자도 바뀌지 않았습니다
- 바뀐 것은 거기 앉을 사람뿐입니다
- 근거가 없으면 없앨 수 없습니다

**화면에 실제로 뜨는 문장** (캡처와 대조해서 확인됨)

- "2명이 아직 받지 못했습니다 — 허주영 · 웅이아버지"
- "허주영 · 웅이아버지 에게 먼저 흘려보내면 모일 이유가 사라집니다"
- "참석 후보 3명 전원이 이 내용을 이미 주입받았습니다"
- "조건을 전부 충족해 회의 없이 종료했습니다"
- "이 유형은 제목과 본문을 읽지 않습니다"
- "여기서 AI 는 하나를 고르지 않습니다 — 판단을 사람에게 넘깁니다"
- "확인하지 못한 조건이 있으므로 삭제하지 않고 비동기로 종료합니다"
- "이 안건의 작업 소유자입니다" / "근거에 등장하지 않습니다"

# 용어 통일표

**슬라이드와 화면의 글자가 다르면 판정이 신뢰를 잃습니다.** 아래로 통일하세요.

| 쓸 것 | 쓰지 말 것 |
|---|---|
| 판정 | 분석 · 예측 · 추천 |
| 근거 | 데이터 · 인사이트 |
| 조건 | 체크 항목 · 기준점 |
| **확인 불가** | 알 수 없음 · N/A · 미확인 |
| 주입 / 전달됨 | 동기화 · 공유 |
| 회의 없음 (`DELETE`) | 회의 취소 · 회의 삭제 |
| 축소 개최 (`SHRINK`) | 회의 최적화 |
| 세션 요약 | 로그 · 리포트 |

**금지어**: "AI 가 알아서" — 이 제품은 판단을 **사람에게 넘기는** 게 특징입니다.
그 반대로 들리는 말은 쓰지 마세요.

# 기술 스택 (질문 나올 때만)

- Next.js · TypeScript · Supabase (서울 리전) · Vercel
- 판정 엔진은 순수 함수 — DB·네트워크 없이 회귀 테스트가 돕니다 (`npm run check:rules`)
- LLM 은 두 곳에만: 회의 유형 분류, 세션 요약
- 훅은 셸 스크립트 — `jq` 같은 외부 의존성 없음
- 판정마다 규칙 버전이 박힘 (현재 `2026-08-p1.2`)
