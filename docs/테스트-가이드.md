# TeamSync 실제 테스트 가이드

두 사람 이상이 각자 노트북에서 실제로 돌려보는 절차입니다. 처음부터 끝까지 30분.

**웹**: https://teamsync-ruddy.vercel.app

---

## 0. 준비물

| | 확인 방법 |
|---|---|
| Claude Code CLI | `claude --version` → 2.x 이상 |
| Node.js | `node -v` → 18 이상 |
| git | `git --version` |
| GitHub 계정 | 테스트 레포를 만들 사람만 |

Claude Code가 없다면:

```sh
npm install -g @anthropic-ai/claude-code
claude          # 처음 실행하면 브라우저가 열리고 로그인합니다
```

> 로그인은 **브라우저 창이 필요합니다.** 터미널을 직접 열어서 해야 하고,
> 다른 도구 안에서 실행하면 TTY가 없어 실패합니다.

로그인됐는지 확인:

```sh
claude -p "한 단어로만 답해: OK"
```

`OK` 가 나오면 준비 끝입니다.

## 1. 테스트용 GitHub 레포 만들기 (한 사람만)

같은 코드를 여러 명이 만져야 "동료의 변경이 나에게 도착하는" 상황이 만들어집니다.

### 방법 A · 웹에서

1. https://github.com/new
2. Repository name: `hankki-test`
3. **Public**, `Add a README file` 체크
4. Create repository

### 방법 B · CLI로 (gh 설치돼 있다면)

```sh
gh auth login          # 처음 한 번. 브라우저가 열립니다
gh repo create hankki-test --public --clone --add-readme
cd hankki-test
```

### 테스트용 코드 넣기

일부러 **서로 얽힌 파일**을 둡니다. 한 사람이 함수 시그니처를 바꾸면
다른 사람이 영향을 받는 구조여야 이 도구가 하는 일이 드러납니다.

```sh
mkdir -p coupon cart order

cat > coupon/discount.ts <<'EOF'
export type Coupon = { code: string; type: "fixed" | "rate"; value: number };

/** 쿠폰 할인 금액을 계산한다. */
export function calcDiscount(total: number, coupon: Coupon): number {
  if (coupon.type === "fixed") return Math.min(coupon.value, total);
  return Math.floor(total * coupon.value);
}
EOF

cat > cart/total.ts <<'EOF'
import { calcDiscount, type Coupon } from "../coupon/discount";

export function cartTotal(items: { price: number; qty: number }[], coupon?: Coupon) {
  const sum = items.reduce((n, it) => n + it.price * it.qty, 0);
  const discount = coupon ? calcDiscount(sum, coupon) : 0;
  return sum - discount;
}
EOF

cat > order/status.ts <<'EOF'
export type OrderStatus = "pending" | "cooking" | "delivering" | "done";
export function isDone(s: OrderStatus) { return s === "done"; }
EOF

git add -A && git commit -m "init: 쿠폰·장바구니·주문상태" && git push
```

다른 사람들은 이 레포를 클론합니다:

```sh
git clone https://github.com/<계정>/hankki-test.git
cd hankki-test
```

---

### 연결할 폴더의 조건 (여기서 제일 많이 막힙니다)

**git 저장소여야 하고, 현재 브랜치가 화이트리스트 안이어야 합니다.**

```sh
cd <연결할폴더>
git rev-parse --abbrev-ref HEAD    # main / develop / feature/... 중 하나여야 함
```

- **git 저장소가 아니면** 브랜치를 못 읽어 전송이 막힙니다. 에러도 안 뜹니다.
- **`master` 라면** 화이트리스트 밖입니다 → `git branch -M main`

기본 화이트리스트는 `main`, `develop`, `feature/*` 입니다.
바꾸려면 `.claude/settings.json` 의 `env` 에:

```json
"TEAMSYNC_BRANCHES": "main develop feature/* hotfix/*"
```

## 2. TeamSync 가입 · 프로젝트 만들기

### 팀장(한 사람)

1. https://teamsync-ruddy.vercel.app → **회원가입**
   - 이름은 실명이나 평소 호칭. **동료의 에이전트가 이 이름으로 부릅니다.**
2. **프로젝트 만들기**
   - 이름: `한끼 배달앱` — 화면 표시용. 아무거나 됩니다
   - 프로젝트 ID: `hankki` — 주소(`/p/hankki`)에 쓰입니다
3. 만들어지면 **6자리 참여 코드**가 나옵니다. 팀원에게 알려주세요.

> **GitHub 레포 이름이나 폴더 경로와 같을 필요가 없습니다.** 전부 독립입니다.
> TeamSync는 GitHub 레포를 알지도, 저장하지도 않습니다. 폴더 경로는 사람마다
> 달라도 됩니다.
>
> 프로젝트 ID 지을 때 두 가지만: **전역에서 유일해야 하고**(다른 팀이 이미 쓰는
> 이름이면 거부됩니다), 주입 블록 맨 앞에 `[hankki]` 로 찍혀서 받는 에이전트가
> 관련성을 판단하는 근거가 됩니다. `test123` 보다 알아볼 수 있는 이름이 낫습니다.

### 팀원(나머지)

1. 같은 주소에서 **회원가입**
2. **참여 코드로 들어가기** 에 6자리 코드 입력

참여하면 **각자의 훅 토큰**이 발급됩니다. 팀이 하나를 나눠 쓰는 게 아닙니다.

## 3. 훅 설치 (각자)

TeamSync 저장소를 받습니다. **연동할 프로젝트와는 다른 곳에 둡니다.**

```sh
git clone https://github.com/jungee123213/unithon-2026.git ~/teamsync
```

프로젝트 화면에서 `토큰 보기` → 설치 명령을 복사합니다. 이런 모양입니다:

```sh
cd ~/teamsync
TEAMSYNC_TOKEN=tsk_... \
  ./hooks/install.sh ~/hankki-test 지우 hankki https://teamsync-ruddy.vercel.app
```

| 자리 | 넣을 것 |
|---|---|
| `~/hankki-test` | **1단계에서 클론한 테스트 레포 경로** |
| `지우` | 본인 이름 (화면에 이미 채워져 있습니다) |
| `hankki` | 프로젝트 ID |

설치 확인:

```sh
cat ~/hankki-test/.claude/settings.json
```

`TEAMSYNC_TOKEN`, `TEAMSYNC_PROJECT_ID`, `TEAMSYNC_MEMBER` 가 보이면 됩니다.

## 4. 첫 세션 — 보내는 쪽

**A(지우)** 가 공유 함수를 바꿉니다.

```sh
cd ~/hankki-test
claude
```

에이전트에게 이렇게 시킵니다:

```
coupon/discount.ts 의 calcDiscount() 반환값을 number 에서
{ amount, reason } 객체로 바꿔줘. 할인이 0원일 때 쿠폰이 없어서인지
조건 미달인지 구분해야 해서야. cart/total.ts 가 이 함수를 쓰는데
그건 아직 고치지 마.
```

작업이 끝나면 **세션을 끝냅니다**:

```
/clear
```

> `/clear` 하거나 창을 닫는 순간 전송됩니다. 세션이 끝나야 보냅니다 —
> 작업 도중에는 아무것도 나가지 않습니다.

### 도착했는지 확인

**웹의 디버그 창**: https://teamsync-ruddy.vercel.app/p/hankki/debug

`생성됨` 이 뜨면 성공입니다. 요약 생성에 5~10초 걸립니다.

로컬 로그로도 볼 수 있습니다:

```sh
tail -10 ~/.claude/teamsync/teamsync.log
```

`POST /api/ingest -> 200 {"ok":true,"skipped":false,"context_id":...}` 가 보이면 도착한 겁니다.

## 5. 두 번째 세션 — 받는 쪽 (여기가 핵심)

**B(민서)** 는 A가 뭘 했는지 **듣지 않았습니다.** 그냥 자기 일을 시작합니다.

```sh
cd ~/hankki-test

```

```

```

B의 에이전트가 **A의 변경을 이미 알고 있어야 합니다.** `calcDiscount()` 가
객체를 반환하니 `.amount` 로 받아야 한다는 얘기가 나오면 성공입니다.

### 직접 확인하고 싶다면

## 6. 안 되는 것도 확인 (중요)

### 개인 브랜치는 전송되지 않는다

```sh
cd ~/hankki-test
git checkout -b wip/실험
claude
# 아무 작업이나 하고 /clear
```

디버그 창에 **아무것도 안 뜹니다.** 훅이 전송 자체를 안 합니다.
`main`·`develop`·`feature/*` 밖은 자동 제외됩니다.

```sh
tail -3 ~/.claude/teamsync/teamsync.log
# → 브랜치 'wip/실험' 화이트리스트 밖 → 전송 안 함
```

### 팀과 무관한 세션은 저장되지 않는다

```sh
git checkout main
claude
```

```
점심 뭐 먹을지 같이 고민해줘. 김치찌개랑 돈까스 중에.
```

`/clear` 후 디버그 창에 **`건너뜀 · L3 · 팀에 영향 없다고 판정`** 이 뜹니다.
요약 AI가 판단한 것이고, 사람이 설정한 게 아닙니다.

### 잠깐 끄기

```sh
touch ~/hankki-test/.teamsync-off     # 끄기 (읽기·쓰기 모두)
rm ~/hankki-test/.teamsync-off        # 켜기
```

## 문제 해결

### 아무 일도 안 일어난다

```sh
tail -20 ~/.claude/teamsync/teamsync.log
```

| 로그 | 원인 |
|---|---|
| 파일 자체가 없음 | 훅이 안 걸림. 그 폴더에 `.claude/settings.json` 이 있는지 확인 |
| `보낼 것 없음 (짧거나 빔)` | 누적 300자 미만. 좀 더 실질적인 작업을 시켜보세요 |
| `브랜치 ... 화이트리스트 밖` | 개인 브랜치이거나 `master`. `git checkout main` |
| 로그는 있는데 flush 기록이 없음 | 그 폴더가 git 저장소가 아님. `git init && git branch -M main` |
| `.teamsync-off` | 킬 스위치가 켜져 있음 |
| `pull: 응답 없음` | 서버 응답이 4초를 넘음. 다음 세션에서 다시 시도됩니다 |

### 자세히 보고 싶다

`.claude/settings.json` 의 `env` 에 추가:

```json
"TEAMSYNC_DEBUG": "1"
```

훅이 숨기던 에러가 전부 로그에 남습니다.

### 세션이 끝났는데 안 갔다

전송은 세션 종료와 **분리된 프로세스**로 나갑니다. 5~20초 걸릴 수 있습니다.
서버가 죽어 있었다면 다음 세션 시작 때 자동으로 재시도합니다.

```sh
ls ~/.claude/teamsync/pending/     # 재시도 대기 중인 것
```

## 자주 나오는 질문

**내 코드가 서버로 가나요?**
아니요. 에이전트가 남긴 **요약문**만 갑니다. 코드는 전송되지 않습니다.
디버그 창과 Team Space에서 실제로 저장된 문장을 그대로 볼 수 있습니다.

**다른 프로젝트 작업이 섞이나요?**
섞이지 않습니다. 훅은 **설치한 폴더**에서만 돌고, 토큰이 프로젝트를 결정합니다.

**API 키 같은 게 새어 나가나요?**
요약 프롬프트에서 한 번, 정규식으로 한 번 총 두 번 거릅니다
(`sk-`, `ghp_`, `Bearer`, 이메일, 32자 이상 hex).

**세션 끝날 때 느려지나요?**
아니요. 전송이 분리된 프로세스로 나가서 세션 종료를 붙잡지 않습니다.

**같은 레포를 써야 하나요?**
아니요. 프로젝트 ID만 같으면 연결됩니다. 다만 진행사항 문서의 브랜치·머지 상태는
각자 로컬 git에서 읽으므로, 같은 레포를 쓰면 그 화면이 자연스럽게 나옵니다.
